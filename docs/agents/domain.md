# Domain Docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root: domain terminology.
- `docs/adr/`: numbered architecture decision records.

## Before exploring

Read `GLOSSARY.md` and the ADRs relevant to the area being explored.
If these documents do not exist, proceed silently. Create them through
`domain-modeling` when terms or decisions are resolved.

## Vocabulary

Use the glossary's terms in issue titles, proposals, hypotheses, and tests.
If a needed concept is absent, check existing project language and note a
real terminology gap for `domain-modeling`.

## Decisions

Explicitly identify any proposal that conflicts with an existing ADR.
Reference the ADR and explain why the decision should be reconsidered.
